## 0. Conventions

- **Desktop sizes only.** The window min width is 840px (`apps/desktop/src/window/DesktopWindow.ts:399`), so Tailwind `sm:` (>= 640px) and `md:` (>= 768px) variants always apply. Every size below is the `sm:`/`md:` value.
- **1rem = 16px by default, 1 spacing unit = 4px.** The interface font size setting (12-20, default 16) sets the root font size, so it scales every rem-based dimension; GPUI's rem size is the same knob.
- **Colors are sRGB `#RRGGBBAA`**, channel-clipped, resolved from the compiled CSS by `tools/resolve-css.mjs` (culori 4.0.2). They map 1:1 onto `gpui::rgba(0xRRGGBBAA)` and onto `t3_ui::tokens::hex`.
- **Alpha colors are not pre-composited.** Paint them with alpha over whatever surface is below.
- **`token/NN`** is Tailwind's opacity modifier: `bg-foreground/8` compiles to `color-mix(in oklab, var(--contrast-foreground) 8%, transparent)`, which keeps the color and multiplies alpha. Utilities resolve through `@theme inline`, so `foreground` means `--contrast-foreground`, `border` means `--contrast-border`, and so on (identical values at the default contrast).
- **Component library.** The primitives in `apps/web/src/components/ui/*` are the coss UI registry on Base UI 1.5.0. Base UI is unstyled; every visual value comes from Tailwind classes.
- **Edge bevel.** coss surfaces still draw a `::before` 1px edge line: light `0 1px black/4` (bottom row), dark `0 -1px white/6` (top row), suppressed on focus, press, disabled and invalid.

### 2.2 Window background and grain

- `html` and `body` paint `--app-chrome-background` (= `--background`).
- **Grain** (`index.css:1666-1690`): the 256px `feTurbulence` tile (baseFrequency 0.9, 4 octaves) at **opacity 0.035**, baked into the SVG. GPUI has no backdrop blur (risk 1), so these need a tint-only approximation.

**GPUI:** `t3_ui::window::NoiseOverlay` is the tile at 3.5%; place it first inside an opaque surface, behind its content.

### 3.1 Families

**GPUI:** nothing is bundled. Sans is `.SystemUIFont` (`t3_ui::tokens::font::SANS`). GPUI's CoreText rasterizer applies stem darkening unless the user disabled `AppleFontSmoothing` (`gpui-pre-macos/src/text_system.rs:218-255`), so GPUI text is slightly heavier. See risk 5.

## 4. Spacing, radius, borders, shadows

### 4.1 Spacing

4px units. The coss controls still use `N x 4 - 1px` horizontal padding so text lines up with 1px-bordered siblings. New semantic insets: `--sidebar-content-inset` 8, `--sidebar-row-content-inset` 10, `--command-shell-inset` 8, `--command-content-inset` 16, `--floating-content-inset` 12 (`index.css:88-106`).

### 4.2 Radius

`--radius` is still 10px, and the scale derives from it: `sm` 6, `md` 8, `lg` 10, `xl` 14, `2xl` 18, `3xl` 22 (`index.css:265-270`), plus `xs` 2 and `rounded` 4. **New:** `--control-radius: 0.5rem` (8px) is what buttons, toggles and other controls use (`ui/button.tsx`: `rounded-[var(--control-radius)]`). `t3_ui::tokens::radius::{CONTROL, SM, MD, LG, XL, XL2, XL3}`.

### 4.3 Borders

1px, default color `border` (`--contrast-border`) on every element (`index.css:647`); form controls use `input`.

### 4.4 Shadows

Tailwind's `shadow-xs/5` ... `shadow-lg/5` and `shadow-sm` are unchanged (`tokens.json > shadow`). New:
- `--shadow-composer: 0 12px 28px -18px rgb(0 0 0 / 40%)`, dark `0 14px 32px -18px rgb(0 0 0 / 75%)` (`index.css:184-185`).
- `dialog-glass`: `0 24px 64px -24px rgb(0 0 0 / 65%)`, dark `inset 0 1px white/4` plus `0 24px 72px -20px rgb(0 0 0 / 90%)`.
- Solid buttons keep `0 1px 2px primary/24` plus `inset 0 1px white/16` (`black/8` pressed).

GPUI 0.3.7 renders inset shadows (`BoxShadow::inset`), clipped to the element.

### 4.5 Opacity conventions

Disabled controls are still 64% (`disabled:opacity-64`, plus `aria-disabled` now). Control icons take `--control-icon-color` (current color by default; `contrast-muted-foreground` on outline and ghost buttons) instead of July's blanket 80% icon opacity.

## 9. gpui-component 0.7 theme mapping

gpui-component's widgets (text inputs, lists, scrollbars, popup positioning) paint from its own `Theme`. `tokens.json > gpuiComponentTheme` is a generated ThemeSet (`tools/tokens.mjs`, `gpuiTheme()`), loaded by `t3_ui::theme` through `ThemeRegistry::load_themes_from_str` and `apply_config`. Key choices:
- Foreground roles use the `--contrast-*` tokens (what Tailwind utilities paint), surfaces the base tokens: `background`, `popover`, `accent`, `muted`, `primary`, `secondary`, `sidebar`.
- Hover and active colors are the fork's opacity utilities (`primary/90`, `secondary/90`, `secondary/80`, `destructive/90`).
- `scrollbar.thumb` is `--app-scrollbar-thumb` (opaque light grey in light mode).
- `font.family` is `.SystemUIFont` and `mono_font.family` is `SF Mono`. t3-ui then overrides the mono family with `Theme::mono_family()`. `radius` is 8 (control radius) and `radius.lg` is 10.
- `Root` paints the theme background (the window is opaque now; the July transparent-root override is gone).
- `theme.focus_ring = false`: t3-ui draws the coss focus rings itself.

gpui-component facts that still constrain the port: `selection` alpha is capped at 0.3; popovers have no border and their own shadow; `TitleBar` is 34px with an 80px pad. Use t3-ui primitives for anything visible.

## 10. Open questions and risks

1. **No in-window backdrop blur in GPUI.**
   - The composer glass (blur 16px + saturate 125% over the scrolling timeline) is the most visible case. Dialog backdrops (4px) and the toast orb (8px) also blur.
   - Options: raise the composer tint to about 85-92% card, sample a pre-blurred offscreen texture, or contribute a backdrop-blur primitive to GPUI.
   - Decide before building the composer.
2. **(Resolved) Native material mismatch.** The fork dropped vibrancy; the window is opaque.

   July note: GPUI's `Blurred` uses `NSVisualEffectMaterial::Selection` and strips the desktop tint and saturation. Electron uses `UnderWindowBackground` with both. Use `Transparent` plus a custom NSVisualEffectView (§2.4). That needs about 40 lines of objc via `raw-window-handle`. Verify against a screenshot of the Electron app over the same wallpaper.
3. **Color management.**
   - GPUI's Metal layer is `BGRA8Unorm` with no colorspace set (`gpui-pre-apple-0.3.7/src/metal_renderer.rs:159`), so values likely go to a P3 display unmanaged.
   - Chromium color-manages sRGB hex and paints out-of-sRGB oklch tokens (`*` in §1.2: info, success, warning, red-400/700, emerald, amber) in true P3.
   - Neutrals are unaffected. Saturated status colors may differ in both directions.
   - Compare side by side on the target display. Consider setting the layer colorspace to sRGB, or shipping P3 values (`tokens.json > outOfSrgbGamut`).
4. **(Resolved) Which mono font the reference renders.** `ui-monospace` -> the system monospaced font (SF Mono) on macOS; GPUI resolves it as `.AppleSystemUIFontMonospaced`.

   July note: The stack starts with "SF Mono", which only matches if the user installed it. Check DevTools "Rendered Fonts" on the reference Mac before choosing JetBrains Mono vs SF Mono.
5. **Font smoothing.** The fork renders `-webkit-font-smoothing: antialiased` by default (no stem darkening); GPUI's CoreText path darkens stems unless `AppleFontSmoothing` is 0. Compare text weight side by side; matching may need a GPUI patch to turn dilation off.

   Obsolete July note (DM Sans is gone): The web loads DM Sans at opsz 14, wght variable, with the family name "DM Sans 9pt" in the name table. Static instances must use opsz 14, and the family name must be fixed. Line-height and baseline metrics differ slightly between Chromium and CoreText, so verify text vertical centering in 28/32px controls with screenshots.
6. **Selection highlight.**
   - Chromium uses the macOS system highlight, which follows the user's accent color and goes gray in inactive windows. The values given are for the blue accent and still need checking.
   - gpui-component's 0.3 alpha cap makes dark mode unmatchable through the theme. Paint selection ourselves, or patch the cap.
7. **Bevels and inset shadows.** Every coss surface has a 1px `::before` edge and solid buttons have an inset highlight. GPUI has neither pseudo-elements nor inset shadows, so overlay children are needed. Easy to forget and visible in light mode.
8. **Grain placement.** The grain now paints behind content (body background and `surface-grain` surfaces), not over the main column.

   July note: You need a pre-rasterized 256px tile. Its z-order quirk must be reproduced: paint it after all main-column content, composer included, but before the sidebar, the sidebar toggle and any overlays. Otherwise the sidebar will look grainier than the reference.
9. **Continuous animations** (§8.2). The fork now duty-cycles them itself (stepped keyframes, paused offscreen), which maps directly onto GPUI's `Animation::with_max_fps` plus a visibility check.
10. **Sidebar tokens now exist.** July's undefined `--sidebar-*` tokens are defined at fe7d3092c (§1.3), so sidebar hovers do paint. `--font-heading` is still undefined, so headings use the sans. Re-check the rail hover in the shell spec.
11. **Behavior parity worth testing:**
    - Select's `alignItemWithTrigger` overlay placement, which gpui-component's Select doesn't do
    - popovers closing instantly while tooltips fade
    - the 600ms tooltip delay and instant phase
    - toast stacking geometry
    - the sidebar drag rejecting widths that leave main under 640px
    - the right panel switching to a sheet at 980px or narrower
12. **Windows and Linux.** The topbar is 40px and the glass composites over `#0A0A0A` / `#FFFFFF` (§2.5). GPUI's Windows backend offers Mica, which Electron doesn't use. Use `Opaque` there for parity.
13. **Tool-call morph uses `filter: blur(3px)`.** GPUI has no element blur, so approximate with opacity and translate only.

### Regenerating and verifying

All scripts read the fork at `$T3_FORK` (default `~/L-Projects/t3UI-refs/t3code-fork`) and resolve packages from its pnpm store, so a dependency bump never leaves a tool on an old copy. Scratch output goes to `$T3SPEC_TMP` (default `/tmp/t3spec`).

```
node docs/spec/tools/compile.mjs        # compile index.css with the fork's Tailwind -> out.css, out.optimized.css, candidates.json
T3_LEGACY_FIELDS=$(grep -oE "pub [a-z_0-9]+: Hsla" crates/t3-ui/src/tokens/generated.rs | awk '{print $2}' | tr -d ':' | sort -u | tr '\n' ,) \
  node docs/spec/tools/resolve-css.mjs  # evaluate the cascade -> resolved.json
node docs/spec/tools/tokens.mjs         # docs/spec/tokens.json
python3 crates/t3-ui/tools/gen_tokens.py   # t3-ui color constants, palette, gpui-component theme
node docs/spec/tools/cls.mjs 'shadow-lg/5' 'dropdown-glass'   # print any utility's compiled CSS
node docs/spec/tools/woff2names.mjs <file.woff2>              # dump font naming tables
```

`resolve-css.mjs` evaluates custom properties the way Chromium does for the default appearance: the cascade by specificity and order for `<html>` and `[data-app-sidebar]` in light and dark, `@supports (color: color-mix(...))` as supported, `var()` substitution per scope, `color-mix()` per CSS Color 5 (premultiplied, percentage normalization) and `light-dark()` by color scheme. Sections it cannot derive (motion, most layout) are listed in `tokens.json > $meta.carriedOver`.
