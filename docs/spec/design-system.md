## 0. Conventions

- **Desktop sizes only.** The window min width is 840px (`apps/desktop/src/window/DesktopWindow.ts:278`), so Tailwind `sm:` (>= 640px) and `md:` (>= 768px) variants always apply. Every size below is the `sm:`/`md:` value. `lg:` (>= 1024px) varies with window width and is called out where used.
- **1rem = 16px, 1 spacing unit = 4px** (`--spacing: 0.25rem`). Nothing overrides the root font size.
- **Colors are sRGB `#RRGGBBAA`**, channel-clipped, generated by `/tmp/t3spec/colors.mjs` from the compiled Tailwind 4.3.0 output (culori 4.0.2). They map 1:1 onto `gpui::rgba(0xRRGGBBAA)`.
- **Alpha colors are not pre-composited.** `accent` is literally `#0000000A`. Paint it with alpha over whatever surface is below. An "on bg" composite over `--background` is given for reference only.
- **`token/NN`** means "token with its alpha multiplied by NN%". Tailwind compiles `bg-accent/50` to `color-mix(in oklab, var(--accent) 50%, transparent)`, which keeps the hue and multiplies alpha.
- **Component library.** The primitives in `apps/web/src/components/ui/*` are the **coss UI** registry (`apps/web/components.json:20`, shadcn style `base-mira`) built on **Base UI** `@base-ui/react` 1.5.0. Base UI is unstyled, so every visual value comes from the Tailwind classes transcribed below.
- **Edge bevel.** Almost every coss surface has a `::before` overlay that draws a 1px edge line:
  - Light mode: `box-shadow: 0 1px #0000000A`, which sits on the bottom border row.
  - Dark mode: `0 -1px #FFFFFF0F`, which sits on the top border row.

  It is suppressed on focus, press, disabled and invalid. In GPUI, draw it as an absolutely positioned 1px child spanning `radius..width-radius`. An outer `BoxShadow` lands 1px too low.

### 2.2 How the CSS reacts

**Window Controls Overlay (Windows and Linux).**
- `syncDocumentWindowControlsOverlayClass()` (`apps/web/src/lib/windowControlsOverlay.ts:22-40`) adds `.wco` to `<html>` whenever `navigator.windowControlsOverlay.visible`.
- Under `.wco` the following change (`index.css:39-49`):
  - `--workspace-topbar-height` becomes `env(titlebar-area-height)`, which is **40px**.
  - The controls insets come from the native control geometry.
  - `--workspace-native-controls-inset` reserves the caption-button width plus 12px on the right.
- macOS never gets `.wco`. Its topbar is **52px**.

**macOS traffic-light reserve.** `AppSidebarLayout.tsx:16,58-61` sets `--workspace-controls-left: 90px` when running in Electron on Mac. Elsewhere it's 12px.

**Glass classes.** These apply in Electron on every OS:
- `.desktop-glass-window` on the sidebar wrapper (`AppSidebarLayout.tsx:82`) makes `html` and `body` `transparent !important` (`index.css:545-548`). It also removes the titlebar-controls gradient scrim (`:552-554`).
- `.app-sidebar-glass` on the sidebar container (`AppSidebarLayout.tsx:89`, `index.css:518-530`): bg `--app-sidebar-glass`, `backdrop-filter: blur(36px) saturate(145%)`. Its `sidebar-inner` child is forced transparent.
- `.app-main-glass` on `<main data-slot=sidebar-inset>` (`ui/sidebar.tsx:629`, `index.css:532-541`): bg `--app-main-glass`, `backdrop-filter: blur(24px) saturate(125%)`. A **direct** child with `.bg-background` is forced transparent. That child is ChatView's root (`ChatView.tsx:5121`), so the chat column shows the glass.
- These rules are unlayered CSS, so they beat the Tailwind `bg-background` utility that is also on `<main>`.

**There is no toggle.** Glass is always on in Electron. Browser builds keep the opaque `--app-chrome-background`.

### 2.3 Layer stack, macOS, bottom to top

1. **Native material.** NSVisualEffectView, material `UnderWindowBackground` (raw value 21), blending `behindWindow`, state `active`. Electron keeps the macOS desktop tint and saturation boost. The view follows NSApp appearance, which `nativeTheme.themeSource` sets.
2. **`html` and `body`:** transparent.
3. **Main column.** `--app-main-glass` is `#FFFFFFE0` light / `#161616D6` dark: 88% or 84% of `--background` over the material.
4. **Noise.** `body::after` (`index.css:603-612`) is a fixed, full-window SVG `feTurbulence` grain:
   - `fractalNoise`, `baseFrequency 0.9`, `numOctaves 4`, `stitchTiles`
   - 256×256 tile, **opacity 0.035**
   - It paints **above everything inside the main column**, including the composer overlay (z-20) and the titlebar controls (z-50). `<main>` has a `backdrop-filter`, which makes it a stacking context, so its internal z-indexes are contained and the later `body::after` covers it.
   - It paints **below** the sidebar container (`fixed z-10`, also a stacking context), the fixed sidebar toggle (z-50), and every portaled popup, dialog and toast (z-50 / z-100).
5. **Sidebar container** (fixed, z-10). `--app-sidebar-glass` is `#FFFFFF94` / `#1B1B1B85`: 58% or 52% of `--card`. It has a 1px right border in `--border`.
6. **Opaque islands inside main.** These use `bg-background` but are not direct children of `<main>`:
   - right panel (`workspace-inline-panel-viewport`, `PreviewPanelShell.tsx:75`)
   - terminal drawer (`ThreadTerminalDrawer.tsx:1222`)
   - `.surface-subheader` rows (`index.css:213-215`)
   - popovers, dialogs and toasts

The CSS `backdrop-filter`s on the sidebar and main do almost nothing visually. There is no page content behind them, and the native material is not part of the page's backdrop. **Don't try to emulate blur(36px) and blur(24px) in GPUI.** The look comes from the native material plus the alpha tints.

### 2.4 Recreating it in GPUI

**1. Window options.**
```rust
WindowOptions {
    titlebar: Some(TitlebarOptions {
        title: None,
        appears_transparent: true,
        traffic_light_position: Some(point(px(16.), px(18.))),
    }),
    window_background: WindowBackgroundAppearance::Transparent,
    window_min_size: Some(size(px(840.), px(620.))),
    ..
}
```
Default bounds are 1100×780.

GPUI's traffic-light math (`gpui-pre-macos-0.3.7/src/window.rs:727-765`) matches Electron's:
- the titlebar container height is `button_h + 2·y`
- buttons sit at `(x, y)`, with an 8px gap derived from the AppKit frames

With 14px buttons the glyph centers land at y ≈ 25. The 52px topbar center is 26, the same 1px offset Electron has.

**2. Native material.** Don't use `WindowBackgroundAppearance::Blurred`. GPUI's version inserts an NSVisualEffectView with material `Selection`. Its `updateLayer` also hides the `CAChameleonLayer` (desktop tint) and strips the saturation filter (`window.rs:1879-1893,3754-3800`). That is visibly flatter and greyer than Electron.

Instead, use `Transparent` and insert your own `NSVisualEffectView` below GPUI's content view:
- `material = .underWindowBackground` (21)
- `blendingMode = .behindWindow` (0)
- `state = .active` (1)
- autoresizing width and height
- don't touch its layers

**3. Root background must be transparent.** gpui-component's `Root` paints `tokens.background` across the whole window (`gpui-component-0.7.0/src/root.rs:445`). Inside `Theme::update` set:
```rust
theme.tokens.background = ThemeToken {
    color: <opaque --background>,
    background: transparent_black().into(),
};
```
Leave `theme.background` (Hsla) opaque. `ThemeTokens::reconcile` keeps a token-only edit, so `Root`, plus `Dialog`, `Sheet` and `TabBar`, paint transparent. Components that read the `Hsla`, such as Input's light background, stay opaque. This is `theme_color.rs:361-385`.

**4. Paint the layers yourself.**
- The main column fills with `--app-main-glass`.
- The sidebar container fills with `--app-sidebar-glass` and has a 1px right border in `--border`.
- The right panel, terminal drawer and subheaders fill opaque `--background`.

**5. Noise.** Rasterize the exact SVG at `index.css:609` once to a 256×256 RGBA PNG with resvg or Chrome. Tile it at 3.5% opacity over the main column only, beneath the sidebar. It must be a static texture: no animation, no per-frame cost.

**Bundling for GPUI.** GPUI needs TTF or OTF, and variable-axis selection is platform dependent. Generate static instances:
```
fonttools varLib.instancer "DMSans[opsz,wght].ttf" opsz=14 wght=400 -o DMSans-Regular.ttf   # also 500, 600, 700
```
- The source is Google Fonts `ofl/dmsans/DMSans[opsz,wght].ttf`.
- Rename the family to "DM Sans" with ttx or `--update-name-table`. Verify with `fc-scan`.
- Use the same name in `font.family`.
- Weights in use are 400, 500, 600 and one 700.
- Bundle JetBrains Mono Regular and Medium TTF from the JetBrains release.
- Register with `cx.text_system().add_fonts(...)`. gpui-component never loads fonts.

**Synthesized faces (decision).** The fork loads only upright faces: DM Sans Variable (wght) and JetBrains Mono 400/500 normal (`main.tsx:8-10`). Chromium therefore synthesizes every italic and every JetBrains Mono weight above 500. GPUI never synthesizes, so `t3UI/crates/t3-ui/tools/build_fonts.py` bakes Chromium's synthesis into static files registered under the same families:
- **Italics** (DM Sans 400/500/600/700, JetBrains Mono 400/500/700): the upright face sheared by Skia's fake-italic skew, `x += 0.25·y` (about 14°). The true JetBrains Mono italic (cursive `f`, `l`, `a`) never appears in the reference, so it is not bundled.
- **JetBrains Mono bold**: Chromium draws `font-weight: 700` (and xterm's bold) as the 500 face plus Skia fake bold. At 12px that adds about 0.49px of stroke, or 40 units per 1000: stems near 140 units, between the real Bold (126) and ExtraBold (150). The bundled "Bold" is the variable font instanced at wght 760, which matches that stroke weight with designed outlines. Advances are unchanged either way (monospace).
- DM Sans 700 is a real variable-font weight in the reference, so it is a plain instance.

**Rendering:** no `-webkit-font-smoothing` or `antialiased` is used anywhere. macOS Chromium uses grayscale AA, and so does GPUI (`is_subpixel_rendering_supported() == false`). No `font-feature-settings` are set, and optical sizing is moot because opsz is pinned.

## 9. gpui-component 0.7 theme mapping

**Facts** (from `gpui-component-0.7.0`, published 2026-09-28; the repo moved to `longbridge/gpui-kit`, theme code is in `crates/component/src/theme/`):
- `ThemeColor` has 139 `Hsla` fields. A parallel `ThemeTokens` holds `{ color, background }` per field, and many components paint from `tokens`.
- Themes load from JSON `ThemeSet { name, themes: [ThemeConfig] }`. Colors accept `#RRGGBBAA` and Tailwind-style names.
- Hover and active colors are theme fields, filled by fallbacks at load time.
- `Theme::update(cx, |t| …)` is the safe write path.
- Clamps: `selection` alpha is capped at **0.3**; `list_active` and `table_active` at **0.2**.
- Defaults: radius 6, radius_lg 8, font_size 16 (which is also the window rem), mono size 13.
- Button heights: XSmall 20, Small 24, Medium 32, Large 32. Input: 20, 24, 32, 44.
- Popovers have **no border**. Their shadow is a 1px `foreground/10` ring plus `0 4 3 -1` and `0 2 2 -2` at black 10%.
- Focus is a 3px band at `ring/50`.
- TitleBar: 34px tall, a fixed 80px left padding on macOS, traffic lights at (9, 9).

- virtual `List`

- button heights
- 6px vs 10px radius
- popovers without borders and with a different shadow
- `PopupMenu` radius capped at 8px
- a 34px TitleBar with an 80px pad
- danger, info and success buttons tinted instead of solid
- scrollbar thumb radius = `theme.radius`

## 10. Open questions and risks

1. **No in-window backdrop blur in GPUI.**
   - The composer glass (blur 16px + saturate 125% over the scrolling timeline) is the most visible case. Dialog backdrops (4px) and the toast orb (8px) also blur.
   - Options: raise the composer tint to about 85-92% card, sample a pre-blurred offscreen texture, or contribute a backdrop-blur primitive to GPUI.
   - Decide before building the composer.
2. **Native material mismatch.** GPUI's `Blurred` uses `NSVisualEffectMaterial::Selection` and strips the desktop tint and saturation. Electron uses `UnderWindowBackground` with both. Use `Transparent` plus a custom NSVisualEffectView (§2.4). That needs about 40 lines of objc via `raw-window-handle`. Verify against a screenshot of the Electron app over the same wallpaper.
3. **Color management.**
   - GPUI's Metal layer is `BGRA8Unorm` with no colorspace set (`gpui-pre-apple-0.3.7/src/metal_renderer.rs:159`), so values likely go to a P3 display unmanaged.
   - Chromium color-manages sRGB hex and paints out-of-sRGB oklch tokens (`*` in §1.2: info, success, warning, red-400/700, emerald, amber) in true P3.
   - Neutrals are unaffected. Saturated status colors may differ in both directions.
   - Compare side by side on the target display. Consider setting the layer colorspace to sRGB, or shipping P3 values (`tokens.json > outOfSrgbGamut`).
4. **Which mono font the reference actually renders.** The stack starts with "SF Mono", which only matches if the user installed it. Check DevTools "Rendered Fonts" on the reference Mac before choosing JetBrains Mono vs SF Mono.
5. **DM Sans instance and name.** The web loads DM Sans at opsz 14, wght variable, with the family name "DM Sans 9pt" in the name table. Static instances must use opsz 14, and the family name must be fixed. Line-height and baseline metrics differ slightly between Chromium and CoreText, so verify text vertical centering in 28/32px controls with screenshots.
6. **Selection highlight.**
   - Chromium uses the macOS system highlight, which follows the user's accent color and goes gray in inactive windows. The values given are for the blue accent and still need checking.
   - gpui-component's 0.3 alpha cap makes dark mode unmatchable through the theme. Paint selection ourselves, or patch the cap.
7. **Bevels and inset shadows.** Every coss surface has a 1px `::before` edge and solid buttons have an inset highlight. GPUI has neither pseudo-elements nor inset shadows, so overlay children are needed. Easy to forget and visible in light mode.
8. **Noise overlay.** You need a pre-rasterized 256px tile. Its z-order quirk must be reproduced: paint it after all main-column content, composer included, but before the sidebar, the sidebar toggle and any overlays. Otherwise the sidebar will look grainier than the reference.
9. **Continuous animations** (§8.2). Many pulsing sidebar dots can force 120Hz repaints. Use one shared low-fps ticker.
10. **Undefined tokens are intentional.**
    - `--sidebar-*` and `--font-heading` are missing, so sidebar-primitive hovers paint nothing and dialog titles use DM Sans.
    - The sidebar rail has no hover line.
    - Don't "fix" these during the port, or the result will diverge from the reference.
11. **Behavior parity worth testing:**
    - Select's `alignItemWithTrigger` overlay placement, which gpui-component's Select doesn't do
    - popovers closing instantly while tooltips fade
    - the 600ms tooltip delay and instant phase
    - toast stacking geometry
    - the sidebar drag rejecting widths that leave main under 640px
    - the right panel switching to a sheet at 980px or narrower
12. **Windows and Linux.** The topbar is 40px and the glass composites over `#0A0A0A` / `#FFFFFF` (§2.5). GPUI's Windows backend offers Mica, which Electron doesn't use. Use `Opaque` there for parity.
13. **Tool-call morph uses `filter: blur(3px)`.** GPUI has no element blur, so approximate with opacity and translate only.

### Regenerating and verifying
